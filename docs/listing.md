## listing.md

### Listing 模块— 多平台上架与库存联动（v1）

#### 职责
- 记录商品在哪些平台上架
- 管理上架状态与时间
- 在库存变化时发出提醒

---

### 一、核心对象

#### Listing
- `id, storeId`
- `platformId`
- `skuId? / itemUnitId?`
- `listedQty`
- `status`：DRAFT / ACTIVE / SOLD_OUT / DELISTED
- `listedAt / delistedAt`

> Listing 是“展示状态”，不是库存真相源。

---

### 二、库存联动规则（你已选择提醒模式）

1. **ItemUnit 售出**
- 同 ItemUnit 的其它 ACTIVE listings → 生成 DELIST_REQUIRED 提醒

2. **Lot 库存下降**
- 若 `activeListedQty > availableQty` → 生成超卖风险提醒

> v1 不自动下架，只提醒（人工确认）

---

### 三、多平台场景
- 同一 SKU / ItemUnit 可在多个平台上架
- Listing 不锁库存
- 实际库存扣减以 OrderAllocation 为准

---

### 四、与销售模块的关系
- Order CONFIRMED → 触发 ListingAlert
- Listing 状态变化不影响订单与库存

---
### 缺货预售（2026-10-06）

- 新建上架及修改 SKU 上架信息支持开启预售，不设置预售数量上限。中古单件、停用或中古 SKU 不开放缺货预售。
- 可售库存为 0 时，普通 SKU 上架会被拦截；开启预售后必须填写预计发货日期并确认已在销售平台告知买家。新建提交前再次显示当前目的地可售库存和交期确认。ERP 不会替用户修改外部平台。
- 上架保存预售标记、交期、确认账号与时间。预售成交后继续保持 ACTIVE；交期按上海日期过期后，必须先更新上架交期才能继续登记成交。已有订单的承诺日期保留不变。
- 缺货成交保存为带预售标记的 DRAFT 订单，界面显示“预售待补货”，不生成库存分配或发货任务。工作台显示补货入口和延期提醒，并为登记人创建有交期的待办；不会自动发送消息给买家。
- 从订单登记补货采购。到货后人工选择批次分配，先处理同商品、同收货地区更早的预售订单。分配预留库存，全部分配后确认订单，再实际发货扣减补货批次库存。新直售 / 打包销售的可分配量会扣除已有预售欠货需求。
- 取消订单沿用原有释放库存逻辑，并取消预售补货待办。确认订单关闭补货待办，保留成交录入的手续费。
- 预售登记售出使用请求标识防止网络重试重复生成订单；同请求标识改变内容会被拒绝。预售商品当前单独登记售出，不加入打包订单。
- 数据迁移：`20261006090000_listing_presale`。新增字段默认不启用预售，不改变历史上架或历史订单的状态。
- 验证：`presale.test.ts` 验证日期与告知要求；`listing-reservations.test.ts` 覆盖零库存预售、无数量上限、重复提交、旧交期保留、优先分配、取消、分配 / 确认不扣库存、实际发货扣补货库存，以及原现货售出流程。

### 预售与物流联动（2026-10-06）

- 在途数量来自 ERP 已登记的采购首程、仓间转运和已发出集运，不代表快递公司实时轨迹。未发货采购、未发出集运不计在途；采购数量扣除已入库流水，多段物流不重复增加原采购数量；已收货不再计在途。
- 在途明细保留运单号及物流入口，按目的市场/仓库筛选。订单专属采购不抵扣公共补货建议；采购发出后从“已采购待入库”改为“在途”，同一到货安排只抵扣一次。
- 正常预售进入工作台“出售 → 预售待补货”；展示未分配数量、当前市场现货。出现现货标注“有现货待核配”，并不保证后下订单能够越过先下订单或跨仓权限分配。抽屉直接分配，到货数量不足可分批分配；完成后确认订单，再发货。
- 超过预计发货日、尚未发货的预售进入异常，但保留分配、确认或发货操作。没有数量上限。
- 销售页提供“预售待履约”筛选与分币种待履约金额。已接预售计入补货需求，超过销量观察窗口仍未履约的欠货也保留；无销量样本时仅按真实欠货给出补量，不伪造销售预测。
- 财务继续按已确认订单计算销售额，待补货预售单独标记、尚不计销售额或利润。取消后退出预售待履约及补货需求。预计发货日期是下单时的承诺快照。


### 预售与现货合包

同平台、同销售账号、同币种的自有库存 Listing 可以将预售新品与现货组成一张订单。提交前须明确买家同意等齐后一起发货；整单预计日期取所选预售记录最晚的日期。普通商品必须能在共同发货仓足量预留，预售商品允许缺货；现货预留不扣实物库存，只有整单发货才扣库存。预售缺货时订单进入待补货，补货必须分配到约定共同仓，全部分配后再确认订单与发货。中古单件本身不能开启缺货预售，但有货的单件可以与新品预售合包。代卖来源仍需其专用预留结算流程。

预售开关仅作用于当前 Listing。到货后可在编辑上架中关闭预售，恢复普通逐件登记售出；已经生成的订单保留原有交期快照。系统不会自动修改或重新发布外部平台商品。预售记录沿用可连续接单逻辑，若外部平台成交后链接已结束，需要按实际情况在系统下架或重新登记。

未发货预售可在工作台的待补货、待确认或待发货面板填写原因取消。取消释放所有现货预留并关闭相关任务，不产生重复入库，也不自动重新上架已成交的外部商品。已发货订单走售后，不直接取消。本系统取消记录不代替平台退款操作。
