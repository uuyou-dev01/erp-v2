## ui.md

### UI 规范（基于 shadcn/ui）

#### 设计目标

- 操作清晰
- 状态明确
- 风险可见（库存/超卖/待下架）

---

### 一、页面结构规范

#### 页面类型

1. List Page（列表）

- 表格为主
- 支持筛选 / 排序 / 快捷操作

2. Detail Page（详情）

- 分区展示（信息 / 动作 / 历史）

3. Action Modal（动作弹窗）

- 明确影响范围
- 必须展示关键后果（扣库存 / 分摊）

---

### 二、库存相关 UI 约束

- Allocation 操作必须可视化
- 拆分（Split）必须二次确认
- ItemUnit 必须展示照片与成色

---

### 三、状态驱动 UI

- CONFIRMED 前：允许修改
- CONFIRMED 后：只读 + 审计
- 危险操作高亮提示

---

### 四、组件使用原则

- 优先使用 shadcn/ui
- 不自造基础组件
- 所有业务操作封装为 Feature Component

---

### 五、核心交互原则：状态优先、模式分离与渐进披露

Progressive Disclosure（渐进披露）是系统级交互原则，不等于“多点一次”，也不等于“所有表单都放进弹窗”。它要求系统先呈现用户当前需要理解的状态，只在用户表达操作意图后，披露完成该动作所需的字段、选项与后果。

本规则适用于详情页、列表页、设置页、管理页与工作台；专用创建页和以连续录入为首要任务的页面按例外规则处理。

#### 默认模式必须唯一

- 一个页面在默认状态下只能有一个主模式：浏览状态或执行任务。
- 详情、列表和管理页面默认属于浏览模式，先回答“现在是什么情况”。
- 创建、邀请、配置、调整和编辑属于动作模式，由用户主动触发后进入。
- 不得在同一视觉层级同时展开浏览态与完整创建态，让两个主任务争夺注意力。

#### 默认规则

- 页面主层级先呈现当前对象、名单、状态、摘要与历史。
- “添加 / 邀请 / 配置 / 调整”由一个明确的动作入口触发，再在弹窗、抽屉或独立步骤中完成。
- 触发入口使用“动词 + 对象”，例如“添加发货人”，不要只放一个无标签加号。
- 次级动作入口不得比当前状态更醒目；一个区域只保留一个主要动作。
- 动作完成后，在原上下文中给出结果与下一步；列表应刷新并反映新状态。
- 空状态可以直接展示唯一的主动作，但仍不默认展开完整表单。

#### 强制级别

- **必须（MUST）**：详情、列表和管理页面不得默认平铺低频的创建、邀请或配置表单。
- **必须（MUST）**：危险、不可逆或会改变权限/库存/资金的动作，在提交前展示影响范围。
- **应该（SHOULD）**：短动作使用弹窗；需要对照当前页面的复杂动作使用抽屉；长流程进入独立页面或分步流程。
- **可以（MAY）**：高频且可快速撤销的单字段修改使用行内编辑。

#### 何时允许平铺表单

仅当同时满足以下条件时，动作表单才可直接出现在页面主层级：

1. 这是该页面的首要任务，而不是查看状态后的偶发操作；
2. 用户进入页面通常就是为了完成它；
3. 表单足够短，不会压过页面的核心信息；
4. 用户需要持续对照页面内容填写，弹窗会切断必要上下文。

#### 容器选择

- 短、可随时取消、无需跨页对照的动作：使用弹窗。
- 字段较多或需要预览上下文的动作：使用抽屉或分步流程。
- 高频、连续编辑且与当前数据强关联：可使用行内编辑。
- 不可逆或高风险动作：在提交前明确展示影响范围与后果。

#### 合理例外

- 专用创建页：页面标题和用户进入意图都明确是“新建 / 录入 / 导入”。
- 高频工作台：连续录入、批量处理或扫描是页面核心任务。
- 状态驱动的必需动作：例如订单缺少库存分配时，只在对应异常状态下展开处理区。
- 必须持续对照大量上下文的编辑：优先抽屉、分栏或独立编辑页，而不是强行使用弹窗。

例外必须能回答：“用户进入这个页面，通常就是为了立即完成这张表单吗？”如果答案是否定的，应默认收起。

#### 禁止模式

- 列表上方常驻完整的“新建 / 添加”表单。
- 详情页在展示对象信息的同时，默认展开整张编辑表单。
- 同一区域同时出现多个平级创建表单。
- 为了减少点击而提前展示大多数时间不会使用的字段。
- 仅使用无文字加号承载关键业务动作。

#### 检查问题

设计评审时必须回答：

- 用户此刻首先要“看什么”，其次才要“做什么”？
- 这个表单是否只有在用户明确触发动作后才有价值？
- 页面是否同时展示了浏览态和创建态，导致两个主任务争夺注意力？
- 收起动作后，入口是否仍然清楚、可发现、可用键盘访问？
- 当前容器是否与动作复杂度匹配，而不是习惯性使用弹窗？
- 空状态、成功、失败、取消与返回焦点是否完整？

#### 设计与开发验收

新页面和改版页面在评审时必须标注：

1. 默认主模式；
2. 主要状态信息；
3. 主要动作与触发入口；
4. 动作容器（行内 / 弹窗 / 抽屉 / 独立页）及选择理由；
5. 空、加载、失败、成功和取消状态；
6. 键盘焦点进入与返回位置。

存量页面按“核心状态被遮蔽程度 × 表单常驻面积 × 动作使用频率”排序改造，不以表单数量机械判断。
