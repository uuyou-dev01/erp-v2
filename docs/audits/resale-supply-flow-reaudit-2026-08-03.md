# 货盘与倒买倒卖第二轮截图实证审计

> 审计日期：2026-08-03
> 审计范围：采购、质检、物流、库存、货盘、代卖、履约、费用约定与结算
> 判定原则：只有本轮用户界面截图可以证明用户能够使用某项功能；代码、自动化测试和数据库只作为辅助解释。

## 1. 执行摘要

本轮在三个全新 PostgreSQL 数据库和三个本地端口中，以货主、采购管理员、朋友代卖方、第三方发货方、仓库执行员及未授权主体等角色重新操作页面。报告只把本轮截图可见的能力计为“用户能够使用”；fixture、数据库与迁移结果仅用于续接阻断流程或解释页面现象。

总体结论：系统已经具备“小生意货盘”的若干关键骨架——发布货盘不占库存、同一实物库存可被多个渠道展示、成交时才预留、定向合作方可见、采购成本对代卖方隐藏、整批采购可暂记总价并以后分摊、第三方发货地址在接受前隐藏。这些能力均有本轮 UI 截图。

但完整闭环仍不能稳定完成，且存在会影响真实钱货的高风险问题：

- “一物一单”采购最终进入数量型库存批次，没有生成独立单件身份。
- 采购显示已收货，而同一运输段仍显示 `IN_TRANSIT`。
- 已收货后没有可见的部分质检、待复检、退供应商入口，也无法从当前页面把采购库存加入集运批次。
- 利润分成黄金算例中，系统因没有本单运费输入项，把 CNY 30 运费漏出费用基数，40% 分成从正确的 CNY 84 变成 CNY 96。
- 多个关键提交在操作中途出现“请先登录”，页面不保存草稿，也没有继续操作的恢复入口。

因此本轮不建议把“货盘发布成功”视为业务闭环完成。优先级应是：先修单件身份、库存/物流状态和金额计算，再补齐质检、集运、协议版本与取消/退货恢复，最后压缩专业术语和前置配置。

### 2.2 结论等级

- 可直接完成。
- 可以完成但需要绕路。
- 无法完成。
- 页面显示成功但数据错误。
- 权限或隐私错误。
- UI、术语或步骤过重。
- 后端可能存在，但 UI 无法确认。

严重度使用 P0–P3：P0 为金额、库存、单件身份或隐私错误；P1 为核心业务阻断；P2 为明显绕路或难用；P3 为文案、视觉和提示问题。

### 2.3 外部边界

本轮不向真实 Mercari、Yahoo、闲鱼等平台提交数据，不调用真实承运商、海关计税或实时汇率服务。复杂发错货、责任赔付和多方争议不在本轮范围内。

### 5.3 合作约定与金额对账

本轮所有分钱方式都只是双方协议的具体例子，不是系统应写死的标准答案。系统可以提供差价、固定金额、比例、费用扣除后分成、组合方式和人工确认等建议模板，但最终计算必须以双方确认的约定、费用承担方式、币种及协议版本为准。

| 算例 | 预期 |
| --- | ---: |
| 成交价 | CNY 800.00 |
| 采购成本 | CNY 500.00 |
| 平台费 | CNY 40.00 |
| 运费 | CNY 30.00 |
| 发货服务费 | CNY 20.00 |
| 全部扣除后可分金额 | CNY 210.00 |
| 可分金额 40% | CNY 84.00 |
| 不扣采购成本时的可分金额 | CNY 710.00 |
| CNY 710.00 的 40% | CNY 284.00 |

人工确认模式不得自动生成佣金；修改协议后，历史订单必须继续使用成交时的旧版本快照。

| 对账行 | 正确金额 | UI 金额 | 差异 |
| --- | ---: | ---: | ---: |
| 售价 | 800.00 | 800.00 | 0.00 |
| 供货价 / 约定采购成本 | 500.00 | 500.00 | 0.00 |
| 平台费 5% | 40.00 | 40.00 | 0.00 |
| 本单运费 | 30.00 | 无输入项 | -30.00 |
| 第三方发货服务费 | 20.00 | 20.00 | 0.00 |
| 可分金额 | 210.00 | 240.00 | +30.00 |
| 朋友 B 40% | 84.00 | 96.00 | +12.00 |

这里的 P0 不是“利润必须按哪一种固定公式计算”，而是系统没有忠实执行双方已经在协议原文中写明的费用承担方式。系统应允许双方自由约定差价、固定金额、比例、组合公式、费用扣除范围或人工确认；一旦确认，就必须把协议版本和实际费用快照应用到本单。

## 10. P0–P3 问题与最短复现

### P0

1. **A-P0-01：一物一单采购落成普通数量批次。** 采购向导添加“一物一单”数量 1 → 收货 → 打开库存批次；结果显示批次数 1、数量 1，而单件工作台无新 ItemUnit。
2. **A-P0-02：已收货采购仍显示运输中。** 登记发货 → 确认收货 → 返回采购详情；采购状态为已收货，运输段仍为 `IN_TRANSIT`。
3. **B-P0-01：已约定的本单运费没有进入利润分成基数。** 协议写明扣供货成本、平台费、实际运费和服务费 → 售价 800、成本 500、平台费 40、运费 30、服务费 20 → 页面显示 40% = 96，而正确为 84。
4. **C-P0-01：仓库执行员看到成本并可删除单件库存。** 以仓库执行员登录 → 库存管理 → 单件库存；三台相机成本和“删除”按钮全部可见。
5. **B-P0-02：请求方与收款方拥有对方职责的高风险动作。** 朋友 B 打开已请求履约，可见接受/拒绝/发货；打开自己作为收款方的利润结算草稿，可确认或作废。

### P1

6. **A-P1-01：已收货采购无法做部分质检、待复检、退供应商。** 采购详情和工作台都没有下一步动作。

## 11. 四类汇总

### 11.1 无法完成

- 部分质检、待复检、退供应商。
- 把已收货采购库存加入集运并完成等待、合箱、封箱、发出闭环。
- 在登录失效后继续已填写的运输或取消操作。
- 从历史代卖详情确认当时使用的协议版本、付款方和收款方。
- 发货完成后自动生成利润分账并进入朋友 B 的收益。
- 从 UI 完整证明标准品退货回库及 ItemUnit 退回待检。

### 11.2 功能过重

- 代卖上架前必须另外维护平台账号。
- 第三方发货需要可服务节点、跨主体协议、任务接受等配置，但缺少一步式检查清单。
- 货盘高级协议把规则、费用基数、发货主体和渠道配置放在多个页面，普通用户难以形成“我到底怎么分钱”的整体心智模型。

### 11.3 UI 不友好

- 成本确认成功与红色不一致警告冲突。
- 到岸成本不展示到具体 SKU。
- 内部枚举和会计方向术语直接显示。
- 错误集中在表单底部，缺少就地修复链接、顶部摘要和草稿恢复。
- 仓库执行员和未授权账号菜单没有按角色收敛。

### 11.4 数据错误

- 一物一单被创建为普通批次。
- 收货后运输段仍在途。
- 黄金算例漏扣 CNY 30 运费，朋友 B 分成多算 CNY 12。
- 发货成功后没有自动利润结算与收益记录。
- 权限数据错误：仓库执行员看到采购成本并可删除单件库存。

## 12. 简化建议与修复顺序

1. **先修钱、货、身份与权限。** 统一 ItemUnit 创建入口；收货必须关闭对应运输段；利润计算从协议版本快照读取本单真实费用；仓库角色默认隐藏成本并移除删除权限。
2. **再补完整主链路。** 收货后直接进入“通过 / 待复检 / 退供应商”；通过项一键加入集运；取消和退货形成可恢复状态机；历史订单始终显示协议版本、付款方、收款方和逐行费用。
3. **把协议做成可组合约定，不写死佣金模型。** 系统只提供建议模板：固定供货价、固定金额、成交额比例、扣除双方勾选费用后的比例、组合规则或人工确认；双方确认的原文、结构化参数、币种和版本共同构成订单快照。
4. **在同一页给出“本单会怎么算”。** 用生活化逐行预览展示“卖了多少—扣了哪些—谁拿多少”，任何协议正文中提到但系统没有结构化字段的费用都要提醒，而不是静默忽略。
5. **把前置配置变成检查清单。** 在代卖页直接显示并修复“缺销售账号 / 缺可服务发货点 / 缺代发协议 / 缺汇率”，完成一项后回到原表单，不丢输入。
6. **隐藏内部实现语言。** 把 `IN_TRANSIT` 改为“运输中”，`PAYABLE/RECEIVABLE` 改为“你需要支付 / 你将收到”，`BY_QUANTITY` 改为“按件数分摊”；高级字段渐进展开。
7. **最后优化视觉与无障碍。** 错误顶部摘要、自动聚焦首个错误、金额与币种成组、明显的会话过期恢复、角色化导航和高风险删除二次确认。
