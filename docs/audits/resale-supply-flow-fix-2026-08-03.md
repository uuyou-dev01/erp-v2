# 货盘与倒买倒卖流程第一批修复记录

> 修复日期：2026-08-03
> 对照报告：`resale-supply-flow-reaudit-2026-08-03.md`

## 本批已完成

1. 采购明细可明确选择“按数量管理”或“一物一单”；一物一单收货会逐件生成 ItemUnit，不再落成普通数量批次。
2. 采购收货会同步关闭相关在途运输段。
3. 已收货采购可在详情页按明细填写“通过 / 退供应商 / 待复检”，并把单件状态分别更新为可用、退供应商、退货检查。
4. 质检通过的商品可从采购详情直接加入已有或新建集运批次；退供应商和待复检商品不会进入集运。
5. 采购详情显示逐 SKU 到岸总额和单件到岸成本；费用资本化后不再把“商品小计”和“含费用总额”误判为金额冲突。
6. 发货后自动按成交时的合作约定快照生成待确认结算和代卖收益；人工确认模式继续阻止自动算佣金。
7. 结算优先采用发货时实际录入的运费与服务费。实际服务费覆盖协议默认值时，不再继续使用旧默认值。
8. 若利润约定要求扣除尚未发生的本单实际运费，售前页面不再把运费当 0 后显示伪精确分成；发货后按实际费用计算。
9. 结算详情显示付款方、收款方、合作约定原文和版本；历史代卖详情显示成交时锁定的协议版本，并提示当前货盘版本是否已变化。
10. 仓库执行员无法查看 ItemUnit 成本，也不能新增、编辑、删除单件主数据；导航和命令入口按职责收敛。
11. 履约请求方不再拥有服务方的接受、拒绝和发货动作；结算收款方只能查看，确认、付款和作废由付款方财务角色执行。

## 合作约定原则

系统没有把佣金写死为“纯利润比例”。双方可以约定固定供货价、差价、固定金额、成交额比例、指定费用扣除后的比例、组合规则或成交后人工确认。系统只执行双方确认的结构化约定与版本快照；无法确定的实际费用不会被猜测为 0。
