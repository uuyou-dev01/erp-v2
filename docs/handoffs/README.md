# 开发交接规范

本目录用于记录跨会话、跨开发者的版本交接。凡是继续开发商品主档、商品分类、商品情报、移动采集、采购、物流、库存、上架、货盘或财务链路，开始前必须先阅读最新交接文档。

## 后续会话的必做步骤

1. 阅读最新交接文档、`agent.md`、`docs/domain.md` 与相关模块文档。
2. 执行 `git status --short`，确认工作区内是否还有其他会话留下的变更。
3. 先复用现有领域模型、Server Actions、平台适配器和业务入口，不另建平行数据模型。
4. 涉及库存、采购、结算、权限或跨组织数据时，先核对交接文档里的不变量。
5. 完成开发后更新相关模块文档；若改变跨模块流程、数据模型或关键约束，必须新增一份交接文档并更新本索引。
6. 交付前至少执行 `npm run typecheck`、相关 Vitest 和 `npm run build`；涉及关键页面流程时补充 Playwright 或浏览器验收。

## 交接文档至少应包含

- 版本范围与已经完成的业务能力。
- 关键领域模型、页面、API、迁移和配置。
- 不允许破坏的业务与数据不变量。
- 已完成的验证、未执行的验证及原因。
- 已知限制、风险和推荐的下一步。
- 部署与数据迁移顺序。
