# 通用外部任务协作命名设计

日期：2026-09-09  
状态：已确认

## 背景

当前邀请、个人协作中心和关系页面频繁使用“帮忙发货”“仓库负责人”“发货操作员”等说法。这会把一个可长期发展的合作关系描述成单一仓库劳务，也无法容纳后续的信息确认、库存盘点、质检、收货和其他协作任务。

## 设计目标

关系层只表达“这个人受邀参与对方的任务协作”，不预设长期只能发货。具体任务层继续清楚说明本次任务是什么，避免为了抽象而牺牲操作准确性。

## 分层命名

### 关系与入口层

统一使用以下名称：

- 外部任务协作
- 我的协作
- 我的任务
- 任务负责人
- 任务协作者
- 参与合作方任务
- 只参与任务协作

邀请、导航、空态、关系卡片、账号说明和关系管理页面不得把整个关系称为“帮忙发货”或“仓库工作”。

### 具体任务层

任务卡片和详情必须显示真实任务类型，例如：

- 订单发货
- 收货确认
- 库存盘点
- 商品信息确认
- 质检

只有任务确实属于订单发货时，按钮、校验错误和业务说明才使用“发货”。不能把真实的发货动作也全部改成含糊的“处理任务”。

## 角色语义

| 当前技术角色 | 产品名称 | 能力语义 |
| --- | --- | --- |
| `MANAGER` | 任务负责人 | 查看当前协作范围内的任务，进行指派、转交、撤回，也可以领取具体任务 |
| `OPERATOR` | 任务协作者 | 领取或处理分配给自己的具体任务 |
| `BACKUP` | 任务协作者（旧角色） | 仅保留历史数据兼容，不出现在新邀请选项中 |

角色是协作范围内的默认能力，不代表雇佣关系、企业成员关系或职级。

## 页面结构

1. 邀请页标题改为“参与合作方任务”，说明当前邀请的协作范围和数据边界。
2. 接受后进入“我的任务”。任务为空时说明“之后分配给你的任务会出现在这里”。
3. “我的协作”展示关系、范围、角色与待处理任务数。
4. 长期发展区改为“只参与任务协作”和“建立自己的业务空间”。
5. 具体任务卡片显示任务类型；订单任务仍可出现收件信息、物流和发货动作。

## 技术边界

本轮不重命名 `LocationFulfiller`、数据库表、Prisma relation 和已有 migration，避免破坏历史数据。它们作为当前“以仓库为协作范围”的技术适配器继续存在。

新增任务类型时，应复用统一任务入口和角色能力，不再新增一个独立的“某某任务门户”。如果未来协作范围不再依赖仓库，再单独迁移为通用关系模型。

## 验收标准

- 邀请、个人协作导航、空态和关系卡片不再出现“只需要帮忙发货”“仓库负责人”“发货操作员”“我的发货任务”。
- 新邀请角色显示“任务负责人 / 任务协作者”。
- 具体订单任务仍显示其发货属性和必要操作。
- 注册、接受、任务指派、创建自己的 ERP、企业连接、定向共享与撤权链路继续通过。
- 重新生成截图，证明通用命名已覆盖邀请、空态、协作中心和任务负责人视图。
