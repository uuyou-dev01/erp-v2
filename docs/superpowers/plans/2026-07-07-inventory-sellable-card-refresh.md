# 库存看板卡片改造计划

## 目标

库存看板只表达“我自己的可售库存和上架覆盖”，不承担商品情报或公共货盘展示。参考 kingcommerce 的库存流程口径，区分可发货现货、在途库存、单件中古库存和平台上架覆盖。

## 模型口径

- 商品组/SPU：聚合展示容器，用于承载同一商品系列或款式。
- SKU：实际可售规格，例如鞋码、角色、颜色尺码、容量规格；库存、上架、价格和单件记录都应落到 SKU。
- 单件库存：中古/孤品 item unit，属于某个 SKU，可有独立品相、标签、图片和上架记录。
- 库存看板：只统计可发货库存；在途和后续已售待发应与可售库存分开看。

## 本次实现

1. 库存卡片不再展示 SKU 图片，改为紧凑的运营卡片。
2. 卡片顶部展示商品组名称、货盘/仓位、规格 SKU 数量和低库存/可卖状态。
3. 卡片摘要展示现货、在途、单件库存、已覆盖平台数。
4. SKU 行展示规格名、SKU 货号、现货/在途、平台覆盖状态和低库存风险。
5. 卡片操作保留上架、库存明细、商品档案，避免入口缺失。
6. 页面补充库存口径提示：现货是可发货库存，在途和已售待发不混入可售数。

## 验收

- `/inventory/sellable` 卡片无 SKU 图片占位。
- 低库存、未上架、待平台等状态仍可见。
- 点击 SKU 行仍可切换当前 SKU，点击库存明细仍打开详情弹窗。
- “上架”和“商品档案”入口仍可跳转。
- TypeScript、lint/build 或等效检查通过。
