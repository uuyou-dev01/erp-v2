# 货盘市场与代卖协作实施计划

## 背景

当前 `/inventory/sellable` 和 `/listing` 的设计适合回答“我自己的库存有什么、上了什么平台”。接下来要支持“别人的货盘我可以看到、选择代卖、售出后让供货方或仓库代发、最后多币种结算”，所以货盘不能继续等同于本店库存统计。

完整业务蓝图见 `docs/superpowers/specs/2026-07-06-marketplace-resale-design.md`。本计划负责把它拆成可验收的代码阶段，避免只加入口、不补增删改查和业务闭环。

## Phase 1: 货盘市场基础闭环

目标：让系统同时存在“我的库存看板”和“公开/定向货盘市场”。

### 数据

- 新增合作方 `Partner`，用于记录供应商、代卖方、代发方、渠道方。
- 新增合作关系 `TradingRelationship`，用于记录与合作方的关系类型、状态、默认佣金、默认结算币种。
- 新增供给货盘 `SupplyOffer`，用于表达某个店铺发布的可售供给。
- 新增货盘明细 `SupplyOfferItem`，用于支持单个货盘包含多个 SKU 或单件库存。
- 新增货盘可见性 `OfferVisibility`，用于支持公开、仅合作方、指定合作方/店铺可见。

### 路由

- `/inventory/sellable`: 保持为“库存看板”，只看本店库存和本店上架状态。
- `/marketplace`: 浏览别人或自己发布的可见货盘。
- `/marketplace/[id]`: 货盘详情，查看供给方、价格、库存、履约方式、合作约束。
- `/marketplace/new`: 发布新货盘。
- `/marketplace/my-offers`: 我的供给货盘列表。
- `/marketplace/my-offers/[id]`: 我的供给详情和状态操作。
- `/marketplace/my-offers/[id]/edit`: 编辑货盘基础信息、明细、可见性。
- `/settings/partners`: 合作方和合作关系管理。

### 增删改查

- 合作方：创建、编辑、停用、列表。
- 合作关系：创建/更新、停用、列表。
- 货盘：创建草稿、编辑、发布、暂停、恢复、下架、删除草稿、列表、详情。
- 货盘明细：创建时添加至少一条明细；编辑页能展示并更新基础供给字段。
- 可见性：支持全公开、私有、指定可见店铺；多店铺账号下可定向授权其它店铺在货盘市场查看。

### 验收

- Prisma schema 校验通过。
- TypeScript 类型检查通过。
- 主要页面路由可被 Next build 编译。
- 新增页面不依赖不存在的硬编码数据。
- 导航中能从侧边栏进入市场、我的供给、合作方。

## Phase 2: 代卖上架闭环

目标：从别人的货盘创建自己的代卖上架，而不是把别人的库存复制成本店库存。

状态：已实现基础闭环。当前支持从 `/marketplace/[id]` 创建代卖草稿，并在 `/resale` 维护本店代卖记录；暂不生成库存预留、客户订单或结算单。

### 数据

- 新增 `ResaleListing`，连接 `SupplyOffer` 与本店销售平台 `Listing`。
- 记录代卖价格、平台、佣金规则、平台费、预估利润。

### 路由

- `/marketplace/[id]` 增加“创建代卖上架”入口。
- `/resale`: 我代卖中的商品。
- `/resale/[id]`: 代卖详情。
- `/resale/[id]/edit`: 修改代卖价格、平台、佣金假设。
- `/resale/new?supplyOfferId=...`: 从指定货盘创建代卖草稿。

### 增删改查

- 代卖上架：创建、编辑、暂停、恢复、下架、列表、详情。
- 平台联动：需要选择 `Platform`，并沿用现有平台费率和币种。
- 售出前校验：货盘状态、可用数量、合作关系、币种。
- 删除：仅允许删除草稿，已启用或已下架记录保留审计。

## Phase 3: 订单与代发闭环

目标：售出后不能只生成本店出库，还要能生成供货方履约请求。

状态：已实现订单联动履约闭环。当前从 `/resale/[id]` 登记售出时会自动创建销售订单和履约请求；创建时锁定货盘数量，拒绝/取消/订单取消时释放预留，发货时消耗预留并减少货盘可供数量，同时同步销售订单为已发货/已送达。

### 数据

- 新增 `SupplyReservation`，用于锁定货盘数量。
- 新增 `FulfillmentRequest`，用于记录代发请求、收件信息、快递、轨迹、异常。
- `CustomerOrder` 增加来源类型或通过关联表区分本店库存订单和代卖订单。

### 路由

- `/sales/[id]`: 显示订单供应来源。
- `/fulfillment/requests`: 待处理代发请求。
- `/fulfillment/requests/[id]`: 代发详情、更新状态、填快递。
- `/fulfillment/requests/new?resaleListingId=...`: 从代卖记录创建履约请求。

### 增删改查

- 履约请求：创建、接受、拒绝、发货、异常、完成。
- 预留：创建、释放、确认消耗。
- 售后：取消订单时释放预留；发货后不能随意删除。
- 当前边界：已支持从代卖售出自动创建 `CustomerOrder` 和 `FulfillmentRequest`；更复杂的售后退货、部分发货和多行订单拆分仍待增强。

## Phase 4: 多币种结算闭环

目标：区分平台收款币种、货盘结算币种、佣金币种、本位币报表。

状态：已实现基础结算闭环。当前可从已发货/已送达的履约请求生成结算草稿，拆分供货货款、佣金、平台费估算、代发运费，并支持确认、标记支付、作废；生成时会按现有 FX 表写入结算单头和结算行的本位币金额。

### 数据

- 新增 `Settlement` 和 `SettlementLine`。
- 关联 `CustomerOrder`、`ResaleListing`、`FulfillmentRequest`。
- 保存交易时汇率快照，不能只实时换算。

### 路由

- `/finance/settlements`: 结算单列表。
- `/finance/settlements/[id]`: 结算单详情。
- `/reports`: 增加代卖毛利、应收应付、多币种口径。

### 增删改查

- 结算单：生成、编辑草稿、确认、标记支付、作废。
- 结算行：收入、平台费、货款、佣金、代发费、汇兑差异。
- 汇率：锁定订单日/结算日汇率，支持手工覆盖。
- 当前边界：已自动写入 `baseCurrency`、`fxRate`、`baseAmount`；经营报表中的代卖应收应付聚合仍待增强。

## 当前执行范围

截至 2026-08-02，Phase 1 到 Phase 4 的基础闭环均已落地，并补充了经营主体、多账号共享库存、保证配额、真实库存锁定和拆分费用规则。系统现在明确区分：

- 我自己的库存：`/inventory/sellable`
- 我发布给别人看的货盘：`/marketplace/my-offers`
- 我能看到并准备代卖的货盘：`/marketplace`
- 这些货盘/关系属于谁：`storeId`、`partnerId`、`visibility`

当前发布流程不再是单页手填表单，而是四步向导：

1. 从经营主体可访问的库存池选择 SKU 或具体单品；外部供给仍可使用手工模式。
2. 配置共享库存、安全库存、供货价和佣金。
3. 授权内部销售账号或外部代卖方，选择自发货或协议代发主体。
4. 预览库存、渠道、费用拆分后保存草稿或发布。

订单库存规则：上架不占用，订单创建即锁定真实库存，取消释放，发货扣减。需要库存承诺的渠道可以使用保证配额，其余渠道继续共享未保护的余量。
