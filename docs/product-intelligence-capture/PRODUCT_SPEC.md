# 商品情报采集系统 PRD

状态：Web 链接采集 MVP 已实现
最后更新：2026-08-06
目标平台：ERP Web、Chrome/Edge、iPhone、iPad、Safari

## 1. 产品背景

用户在官方商城、二手交易平台、个人卖家页面或 App 中看到商品时，需要快速记录：

- 商品来源和原始链接
- 卖家标题、描述和图片
- 当前价格、币种和成色
- 看到时间
- 它可能对应的 ERP 商品组或 SKU

当前手动进入商品情报页面再逐项填写，打断浏览过程，也容易丢失来源。目标体验应接近 Pinterest 的“保存”动作：先快速留下可靠证据，再在采集箱中完成整理。

## 2. 产品目标

### 2.1 核心目标

1. 在 Chrome 或 Apple 分享菜单中，用一次入口完成采集。
2. 即使宿主 App 只提供链接、文字、图片或截图中的一种，也能创建有效草稿。
3. 重复采集不会制造重复商品或重复描述。
4. 外部卖家信息与 ERP 标准商品严格分离。
5. AI 能减少整理工作，但所有标准商品合并都可解释、可回退。
6. 为未来 SaaS、公共货盘、价格分析和对外 API 保留来源与租户边界。

### 2.2 非目标

- 不做后台批量爬虫。
- 不绕过登录、验证码、付费墙或平台访问限制。
- 不承诺从所有 App 自动读取完整页面。
- 不根据相似标题自动创建或合并 SKU。
- 不把个人卖家描述直接写入标准商品描述。
- 第一阶段不支持 Android。
- 第一阶段不做自动采购、自动上架或自动下单。

## 3. 用户与主要场景

### 3.0 ERP Web 粘贴链接

1. 用户进入商品情报采集箱，粘贴一个公开商品 URL。
2. 系统先读取 Open Graph/JSON-LD；核心字段不足时使用匿名浏览器渲染。
3. 页面内联展示标题、价格、图片、描述、平台 ID、来源类目和内部品类建议。
4. 用户核对价格，选择已有 SKU 或暂不匹配。
5. 保存后建立来源商品与快照；只有选定 SKU 才写入正式价格时间线。

详细规则见 [ERP Web 商品链接采集](./WEB_LINK_CAPTURE.md)。

### 3.1 Chrome 浏览网页

1. 用户点击“采集到 ERP”扩展按钮。
2. 扩展读取当前 URL、页面标题和公开可见元数据。
3. 扩展侧栏展示候选图片、价格和描述。
4. 用户可直接保存，也可选择页面上的价格/图片。
5. Capture API 返回：
   - 已采集过且无变化
   - 价格发生变化
   - 可能匹配已有商品/SKU
   - 新来源，已进入采集箱

### 3.2 iPhone/iPad 从 App 分享链接

1. 用户在任意支持分享的 App 中点击系统“分享”。
2. 选择“ERP 商品采集”。
3. Share Extension 读取宿主 App 提供的 URL、文字、图片。
4. 用户只需确认店铺、价格（可空）和可见范围。
5. 保存后立即返回原 App，详细整理留到 ERP 采集箱。

### 3.3 App 没有提供有效链接

1. 用户截取当前商品页面。
2. 从截图预览或照片 App 分享到“ERP 商品采集”。
3. Apple Vision OCR 在设备端提取文字、数字和位置。
4. 用户可补充来源 App、价格和链接。
5. 系统以低/中置信度进入采集箱，不自动建立 SKU。

### 3.4 再次采集同一来源商品

系统根据 `platform + externalListingId`，其次根据规范化 URL 判断是否已经存在：

- 完全相同：只更新最后看到时间。
- 价格变化：增加价格观察。
- 描述、标题或图片变化：增加快照并展示差异。
- 状态变化：记录在售、售出、删除或不可访问。

## 4. 产品信息分层

### 4.1 标准商品组

ERP 维护的款型/系列身份，例如 `Nike Dunk SB Low 芝加哥`。

保存：

- 标准名称
- 品牌
- 分类
- 官方货号/款号
- 标准描述
- 标准主图

### 4.2 标准 SKU

具体可区分规格，例如 `43码`。只有在外部信息足够明确并经确认后，来源记录才关联到具体 SKU。

### 4.3 来源商品 SourceListing

某个平台上的一个原始页面或卖家商品：

- 平台和来源 App
- 平台商品 ID
- 原始 URL
- 卖家原始标题和描述
- 卖家图片
- 卖家声称的成色、配件、瑕疵
- 首次/最后看到时间
- 在售状态

来源商品不能直接覆盖标准商品字段。

### 4.4 来源快照 SourceListingSnapshot

来源商品在某个时间点的内容版本：

- 标题/描述
- 价格/币种
- 图片集合
- 页面状态
- 内容哈希
- 原始采集包

### 4.5 价格观察

价格必须关联来源商品和快照，并记录：

- 金额、币种
- 价格类型
- 成色
- 运费/税费是否包含（未知也要明确）
- 观察时间
- 来源可信度

## 5. 采集输入

统一接受以下输入：

| 类型          | 必填                   | 说明                     |
| ------------- | ---------------------- | ------------------------ |
| `SHARE_URL`   | URL                    | Apple/浏览器分享链接     |
| `WEB_CLIP`    | URL + 页面元数据       | Chrome/Safari 网页扩展   |
| `SHARE_TEXT`  | 原始文字               | 宿主 App 仅分享标题/描述 |
| `SHARE_IMAGE` | 图片                   | 商品图片或 App 分享图片  |
| `SCREENSHOT`  | 截图                   | OCR 兜底                 |
| `MANUAL`      | 至少一项文字/价格/链接 | 极简手动记录             |

一个 Capture 可以同时包含多种输入。

## 6. 采集箱状态

- `RECEIVED`：API 已接收，尚未处理。
- `PROCESSING`：正在解析、OCR、去重或匹配。
- `NEEDS_REVIEW`：需要用户确认字段或商品归属。
- `READY`：字段充分，可一键归档。
- `IMPORTED`：已创建/关联来源商品及价格观察。
- `DUPLICATE`：内容完全重复，仅更新最后看到时间。
- `FAILED`：处理失败，可重试。
- `DISMISSED`：用户主动忽略。

## 7. 去重和变化规则

### 7.1 确定性去重

按优先级：

1. 平台 + 外部商品 ID
2. 规范化 URL
3. 同来源下的内容哈希
4. 图片文件哈希
5. 客户端幂等键

确定性重复不调用 AI。

### 7.2 模糊候选

以下只用于找候选，不能自动合并：

- 品牌 + 款号
- 品牌 + 系列 + 颜色
- 多语言标题向量
- 图片相似度
- OCR 提取的尺码/规格

### 7.3 描述处理

- 原始描述永久属于来源快照。
- 同一来源、相同 `contentHash` 不重复保存正文。
- 同一来源、描述变化时增加快照并生成 Diff。
- 不同卖家使用相同描述，来源关系仍然分开。
- 标准描述由人工维护，或由多个来源生成“建议稿”后人工确认。

## 8. AI 使用边界

### 8.1 AI 可以做

- 从标题/描述/OCR 中抽取品牌、款号、尺码、颜色。
- 抽取卖家声明的成色、瑕疵、缺件和配件。
- 对跨语言标题做标准化。
- 对候选商品/SKU 重排并说明依据。
- 总结前后两次采集的变化。
- 生成标准描述建议稿。

### 8.2 AI 不可以自动做

- 合并两个标准 SKU。
- 修改标准商品主图或描述。
- 把“卖家声称”升级为确认事实。
- 删除来源商品或快照。
- 仅凭标题相似就建立 SKU 关联。

### 8.3 证据要求

AI 抽取的字段必须同时保存：

- 原文或图片区域
- 来源快照 ID
- 置信度
- 模型/规则版本
- 人工确认状态

## 9. Web 产品界面

新增页面建议：

- `/product-intelligence/captures`：采集箱
- `/product-intelligence/captures/[id]`：采集审核
- `/settings/capture-devices`：扩展/Apple 设备绑定与撤销
- 商品情报详情页新增“来源商品”和“价格时间线”

采集箱顶部提供常驻的“从商品链接采集”入口。解析结果在当前页面展开，不使用阻断式弹窗；原始来源与标准商品归属并排核对。

采集箱默认按以下优先级排序：

1. 价格变化
2. 高置信度待确认匹配
3. 信息不完整
4. 完全重复

## 10. 快速保存体验

快速入口不能要求填写完整商品表单。

最小确认字段：

- 目标店铺
- 来源可见范围
- 价格（识别失败时允许为空）

其余内容进入采集箱后补充。用户在 Apple Share Extension 中保存成功后应立即返回原 App。

## 11. 安全与隐私

- 客户端使用可撤销的设备令牌，不保存 ERP 主账号密码。
- 设备令牌限定 `product-intelligence:capture` 权限。
- 所有记录绑定组织、店铺、用户和设备。
- 截图默认继承用户选择的可见范围。
- 不持续读取浏览历史或 App 屏幕。
- Chrome 默认使用 `activeTab`，不申请永久访问全部网站。
- 保存来源和证据时需要支持用户删除与数据导出。

## 12. 目标版本验收标准

完成 Chrome 与 Apple 两个客户端阶段后，目标版本至少满足：

1. Chrome 可从任意普通商品网页创建 Capture。
2. iPhone/iPad 可从分享菜单提交 URL、文字或图片。
3. 同一个 URL 连续提交不会创建重复 SourceListing。
4. 同一来源价格变化会增加 Observation。
5. 同一来源描述变化会增加 Snapshot。
6. 信息不足的记录进入 `NEEDS_REVIEW`，不会自动创建 SKU。
7. 用户可以把来源记录关联到已有商品组/SKU。
8. 用户可以拒绝 AI 建议且保留原始证据。
9. 设备令牌可以在 ERP 中撤销。
10. Android 不属于本阶段验收范围。
